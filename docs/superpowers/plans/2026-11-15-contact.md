# Closing invitation and local contact demo

User request: add the closing consultation section and contact page, then provide one small exercise. The original brief requires real submission in a controlled test environment and honest delivery status.

## Scope and design

Add a closing invitation after the homepage and studio process sections. Use the existing serif type, ivory/olive palette and one link to `/contact`. Contact uses a short introduction and three labelled fields: name, email and project brief. Explain the local demo before submission. Cover validation, pending, success and failure; keep values after failure. No phone, address, account, booking or external email service is needed.

The endpoint runs as Vite middleware in dev and local preview. It validates independently, accepts same-origin loopback JSON POSTs only, limits body size/time and submission rate, and saves private JSON receipts in `.local/consultations`. The outbox is ignored by Git and denied by the dev file server. Success means a completed local save, never email delivery or a booked appointment. A request ID makes unchanged retries idempotent; atomic writes avoid partial receipts.

Shared validation keeps the UI's hints and server rules consistent. Use built-in Node APIs and the existing React/Vite stack; add only Node development type definitions. Server-only `slow` and `reject` modes support controlled pending/failure checks. They are not client-selectable.

Affected files: App, new Contact component and shared validator, CSS, new server middleware, Vite/TypeScript config, tests, package metadata, `.gitignore`, README and learning notes. Preserve all user edits, including the process grid's `3rem` gap. Gallery interactions and per-page metadata remain later work.
